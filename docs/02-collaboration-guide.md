# Independent Study and Optional Collaboration

You are the learner and primary builder. This project is designed to be completed independently using the repository's [self-study course](learning/README.md), [self-guided manual](04-self-guided-manual.md), [experiment workbook](05-experiment-workbook.md), [implementation blueprint](06-implementation-blueprint.md), and [troubleshooting guide](07-troubleshooting-and-self-review.md). You do not need a mentor, assistant, or check-in to follow the phases.

## Your responsibilities

- Choose a daily learning question and explain the concept in your own words.
- Make and record protocol/design decisions before final comparisons.
- Implement the project yourself and run the experiments.
- Save real outputs, configs, and logs; never replace missing evidence with guessed numbers.
- Decide whether optional features have enough learning value to justify their complexity.
- Verify each portfolio claim against a reproducible artifact or measurement.

## Optional outside help

If you choose to use a tutor, reviewer, or coding assistant, keep it in a supporting role:

- Ask for explanations, small exercises, hints, and reviews of your attempt.
- Make the design choice and write the code yourself.
- Ask for a full implementation only when you explicitly want a reference solution after attempting the task.
- Verify advice against primary material and your own experiment protocol.

The project documents include self-check questions, worked toy examples, answer keys, exit gates, and troubleshooting guidance so this optional support is not a dependency.

## Session workflow

1. Read one lesson and its primary source.
2. Write what you think before checking the explanation.
3. Solve its exercise without copying.
4. Complete one small build ticket only when its prerequisite gate is satisfied.
5. Compare your output with the expected behavior or answer key.
6. Record what happened and what remains uncertain.
7. Move on only when you can explain the idea and reproduce the result.

## Guardrails

- Keep the 85% learning / 15% building balance across the project.
- Do not fabricate metrics, benchmarks, data findings, citations, or outcomes.
- Keep optional technologies optional; every addition needs a learning goal and measurable experiment.
- Prefer a small, understood implementation over a large copied system.
- No external messages, deployments, or privacy changes are part of the project plan.
